# Section 2: Conversation Flow

The Conversation flow is modeled in Virtual Agent Designer using the following node-by-node logic:

```
[Start Node] 
    │
    ▼
[Greeting Node: Welcome & intro]
    │
    ▼
[Input Prompt: Ask for Tracking Number]
    │
    ▼
[Script Action: Regex format validation] ──── (Invalid format) ────► [Retry / Error Node]
    │                                                                       │
(Valid format)                                                       (Too many retries)
    │                                                                       │
    ▼                                                                       ▼
[Script Action: Call EcoComplaintUtils]                               [Escalate / Exit Node]
    │
    ├─── (Record Not Found) ──► [Help/Not-Found Node] ──► Suggest portal tracker link
    │
    ▼
(Record Found)
    │
    ▼
[Success Response Node: Display Citizen-Safe Status & Severity]
    │
    ▼
[Decision Node: Ask for further assistance] ── (New Incident) ──► Link to Intake Portal
    │
    ▼ (No/Quit)
[Exit Node: Friendly farewell]
```

### 1. Greeting / Entry Message
* **Node Type**: Bot Response (Text)
* **Message**: *"Hello! I am EcoSentinel's virtual assistant. I can help you track the status of your citizen environmental report."*

### 2. Prompt for Tracking Number
* **Node Type**: User Input (Text)
* **Variable**: `vaVars.tracking_number`
* **Prompt**: *"Please enter your report tracking number (format: ES-YYYY-MMDD-XXXX):"*
* **Input Validation**: A Decision Node executes a regular expression format check:
  `^ES-\d{4}-\d{4}-\d{4}$` (checking against the unique sequential tracking format generated by `EcoComplaintNumberGenerator`).
  * If validation fails: Prompts with *"That doesn't match the expected format. Let's try again."* (Allowed 2 retries before escalating to human agent).

### 3. Verification Lookup
* **Node Type**: Script Action (Calls reusable Script Include method `EcoComplaintUtils.lookupComplaint()`).
* **Logic**:
```javascript
var trackerNum = vaInputs.tracking_number.toString().trim();
// For portal tracker lookups, we also request the verification email to comply with ACL guidelines
// If conversation is anonymous, prompt for email in step 2.5
var citizenEmail = vaInputs.citizen_email.toString().trim();

var utils = new x_eco.EcoComplaintUtils();
// Mocking Ajax call parameters for server execution
var resultJson = utils.lookupComplaintFromServer(trackerNum, citizenEmail);
var result = JSON.parse(resultJson);

if (result.found) {
    vaVars.record_found = true;
    vaVars.complaint_state = result.state;
    vaVars.complaint_category = result.category;
    vaVars.complaint_ai_severity = result.ai_severity;
    vaVars.complaint_desc = result.short_description;
} else {
    vaVars.record_found = false;
}
```

### 4. Success Response
* **Node Type**: Bot Response (Card/Text)
* **Condition**: `vaVars.record_found == true`
* **Citizen-Safe status translation**:
  The system maps database state codes to natural, comforting sentences to avoid technical ServiceNow jargon:

  | Database State | Citizen-Safe Output Message |
  |---|---|
  | `1` (Received) | *"We have successfully received your report. Our team is preparing to conduct an initial review."* |
  | `2` (AI Verified) | *"Our system has validated the report details. We are matching this to nearby environmental monitoring records."* |
  | `3` (Inspector Assigned) | *"A regional field inspector has been assigned to physically verify the site."* |
  | `4` (Inspection In Progress) | *"Our inspector is currently en route or on-site conducting a physical investigation."* |
  | `5` (Inspection Completed) | *"The physical inspection is complete. Our compliance officers are reviewing the compiled evidence package."* |
  | `6` (Action Taken) | *"A violation was confirmed. A formal enforcement notice has been issued to resolve the issue."* |
  | `7` (Dismissed) | *"Our inspectors completed an on-site investigation. No regulatory violation was confirmed at this location."* |
  | `8` (Closed) | *"This investigation is now closed. Thank you for reporting."* |

* **Citizen-Safe Severity Output**:
  If the severity is **High**, it is presented as: `"Priority: High Response Code"` rather than warning terms that might cause public panic.

### 5. Not-Found Response
* **Node Type**: Bot Response (Text)
* **Condition**: `vaVars.record_found == false`
* **Message**: *"I was unable to find a record matching that number and email combination. Please double-check your receipt or visit our incident tracking webpage to submit a manual check: https://[instance].service-now.com/ecosentinel?id=track"*

### 6. Follow-up Options
* **Node Type**: User Input (Choice)
* **Message**: *"Is there anything else I can assist you with?"*
* **Choices**:
  * `"Report a new environmental incident"` $\rightarrow$ Links user to the Report Incident Record Producer form.
  * `"Connect with a Support representative"` $\rightarrow$ Triggers live agent handoff.
  * `"No, I'm finished"` $\rightarrow$ Ends conversation.

### 7. Exit Message
* **Node Type**: Bot Response (Text)
* **Message**: *"Thank you for helping monitor our environment. Stay safe!"*

# Section 5: Error Handling & Exit Boundaries

* **Lookup Timeout**: If the server-side Script Include takes longer than 8 seconds to execute, the Virtual Agent intercepts the transaction, displays *"The lookup system is taking longer than usual to respond. Let me give you the portal link to check manually: [Link]"*, and logs an integration error flag.
* **Malformed Input Limit**: If the user enters an invalid tracking format 3 times consecutively, the bot automatically exits the input prompt node, stating: *"We're having trouble reading that format. Let me connect you with an agent or redirect you to the main portal."*
* **Conversation Abandonment**: If the user remains inactive for more than 15 minutes, the bot sends a session warning, waits 2 minutes, and then posts a final closing message before terminating the chat context to conserve PDI resources.
